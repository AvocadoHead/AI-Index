# Sphere exploration and linked model cards

## Interaction

The exploration slider and its explanatory text are removed. Negative wheel delta now moves inward (the prior direction is reversed): first the full filtered collection fades into the stationary, transparent sphere; only the second stage moves the viewpoint inside. Positive delta reverses the path. The quiet Outer view / Full collection / Inside buttons remain usable by touch and keyboard; PageUp/PageDown also change depth while the sphere has focus. Vertical touch scrolling remains native; sideways dragging retains rotational inertia. Wheel input releases at boundaries and while a card is pinned. Reduced motion uses immediate explicit controls.

All 164 identities enter the full-collection view. Collision handling and edge fading keep labels readable; this does not claim 164 names are simultaneously readable on a phone. Atlas exposes the complete filtered list. The 66-item starting set, original 120 records and historical numeric scores remain unchanged.

The existing keyed label flight works in both directions between Atlas and sphere. A pinned card is restored for the same identity after the animation, including native mouse clicks on the layout controls. Reversals preserve label positions, and reduced motion skips the flight.

## Model relationships

`data/model-relationships.json` is the dated source-backed graph; `model-relationships.js` is generated by `node scripts/relationships.mjs --write`. It currently contains 12 model-family records and 102 relationship groups across 10 workspaces. Relationship counts include separately labelled documentation, pricing-list and API evidence; they are not a count of account-tested UI selections, popularity or quality.

Cards distinguish providers from workspaces and model families. Family cards link nested model/generation details, and reverse workspace links derive from the same graph. Where a canonical family is not yet present, a model label links to its official source rather than an invented internal identity. Modes such as reference, edit, extend and LoRA remain route labels, not unrelated model families.

- Sync Studio and the Sync lip-sync family are separate identities. sync-3 is the documented default; lipsync-2, 2-pro and legacy 1.9 remain distinct. react-1 is a sibling model. Kolbo evidence supports lipsync-2-pro, not inferred Sync 3 access.
- Seedance links 2.5, 2.0 and earlier generations, with variants nested within the generation. BytePlus deprecation/shutdown dates are scoped to BytePlus, not global family retirement. No 2.1 or “2.5 Turbo” was invented.
- Firefly lists documented product surfaces and restrictions, including individual-account limitations for Kling/Seedance.
- Weave pricing-list evidence and external-client API documentation are labelled separately; neither is promoted to verified UI entitlement.
- Kolbo uses explicitly visible public-registry rows for the selected relationships. Only names and capability/identity facts were transferred. Hidden/unspecified visibility, routers and backend metadata were excluded. This is a curated relationship snapshot, not an exhaustive copy of its registry.
- ChatGPT and Codex remain products, separate from OpenAI and the GPT family. Selector labels, effort modes, plans and rollouts are kept distinct.
- Claude and Claude Code remain separate products, with documented client-version and subscription restrictions.
- Flow and Antigravity show surface-specific access. Argon is not asserted available in Antigravity IDE; planned Omni extension is not presented as current; scheduled November 2 removals are visible.

The snapshot was checked October 14, 2026. Each entry retains official source URLs and dates. No account-level entitlement test, paid generation or benchmark was performed. Unknown input/output modalities are explicitly left unspecified. There are no new quality scores.

## Validation and environment

Visual and interaction checks use **Google Chrome 155.0.8059.41 on macOS**, launched headlessly with isolated temporary profiles. No personal browser session is used.

```sh
node scripts/catalog.mjs
node scripts/editorial.mjs
node scripts/relationships.mjs
node --test tests/*.test.mjs
node scripts/browser-qa.cjs
node scripts/exploration-qa.cjs
node scripts/relationships-qa.cjs
```

The full suite covers 360/390/768/1440 px in Hebrew/English, fonts, score sizing, search and filters, native touch and keyboard, focus/Escape, inertia, flight reversal and fallback modes. Exploration checks use actual wheel/touch/key events and wait for animation completion. Relationship checks traverse every internal family/generation, inspect source links and modal width, and verify pinned selection through native clicks in both layout directions.

No merge or deployment is part of this review. The live release remains `ec5081f356b3eea12e8c66a753c02206c35f8d3a`.
